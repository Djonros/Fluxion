# ReAct-агент

Агент решает задачи по шагам: находит нужные файлы, читает код, вызывает инструменты, проверяет результат и повторяет цикл до завершения. Мысли и итоговый ответ он пишет на языке вашего вопроса; в ответе называет изменённые файлы и как их запустить.

**Бесплатно** агент работает в режиме чтения: находит ошибку и объясняет её. **В Pro** он сам правит файлы и проверяет правки тестами.

## В приложении

Страница **«Агент»**:

1. Опишите задачу в поле сверху (например: «прочитай main.py и объясни, что он
   делает»).
2. Настройте опции: чекбокс **«Разрешить запись файлов (Pro)»** (эквивалент
   `--write`) и лимит шагов (1–50, по умолчанию 15) — в **«⚙ Дополнительно»**.
3. Нажмите **Запустить** — каждый шаг рассуждений и вызовы инструментов видны в
   логе; **Стоп** прерывает выполнение.

Быстрый запуск из чата: включите флажок **«Агент: файлы»** у поля ввода на
странице «Чат» — следующее сообщение уйдёт агенту с инструментами проекта
(запись файлов по-прежнему только в Pro).

## Запуск

```
❯ /agent Fix the failing test in tests/test_parser.py
❯ /agent --write Add docstrings to all public functions in utils.py
```

!!! warning "Без флага `--write` агент только читает"
    Запись файлов (`write_file`, `edit_file`) и `git_commit` доступны только с
    `--write` (Pro). `git_status` и `git_diff` работают и в режиме чтения.
    В CLI лимит шагов задаётся `--iter N` (по умолчанию 50).

## Инструменты

| Инструмент | Описание |
|------------|---------|
| `list_files` | Список файлов проекта (папка или glob, например `**/*.py`) |
| `read_file` | Прочитать файл; длинные файлы читаются по диапазону строк |
| `grep` | Поиск по регулярному выражению во всех текстовых файлах |
| `search_code` | Поиск по смыслу в проиндексированном проекте (RAG) |
| `write_file` | Создать/перезаписать файл |
| `edit_file` | Точечное редактирование |
| `run_tests` | Запустить pytest |
| `web_search` | Веб-поиск: встроенный или SearXNG, если включён |
| `git_status` | Статус рабочего дерева |
| `git_diff` | Показать изменения |
| `git_commit` | Закоммитить изменённые агентом файлы |
| `finish` | Завершить задачу |

`search_code` доступен, когда проект проиндексирован (страница «Проект» или
`/index`). Агент видит только результаты из текущего проекта; если индекс собран
по другой папке, он предложит переиндексировать.

## Формат вызова инструментов

С бэкендами llama.cpp и Ollama агент по умолчанию работает в режиме
**структурированных вызовов**: каждое действие — JSON-объект, а JSON-схема
компилируется в грамматику, так что модель физически не может выдать
некорректное действие (пропущенный путь, выдуманный инструмент, обрывки
`Observation:` в файлах).

```json
{"thought": "Исправлю оператор.", "tool": "edit_file", "path": "calc.py",
 "old": "    return a - b", "new": "    return a + b"}
```

| Переменная | Значение |
|------------|----------|
| `FLUXION_AGENT_FORMAT` | `auto` (по умолчанию), `json` или `text` (классический ReAct) |
| `FLUXION_API_STRUCTURED=1` | Включить JSON-схему для API-бэкенда (только если провайдер поддерживает `response_format: json_schema`) |

Если бэкенд отклоняет схему (например, Ollama старше 0.5), агент автоматически
переключается на текстовый формат в том же запуске. Понимаются оба формата
ответа, поэтому переключение безопасно.

## Git safety

- **Auto-checkpoint** — перед первой записью агент делает снимок рабочей папки
  (`refs/fluxion/checkpoints/`), не трогая ваши незакоммиченные файлы
- **Rollback** — `/rollback` в CLI возвращает проект к состоянию до агента,
  включая удаление созданных им файлов
- **Commit из агента** — коммитятся только файлы, изменённые агентом; `.env` и
  ключи не коммитятся никогда

## API

```bash
curl -X POST http://localhost:8765/api/agent/run \
  -H "Content-Type: application/json" \
  -d '{"task": "Fix the failing test", "allow_write": true}'
```
