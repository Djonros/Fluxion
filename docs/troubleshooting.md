# Решение проблем

Принцип Fluxion — **Zero Silence**: ни одна функция не деградирует молча. Если
что-то недоступно, вы увидите баннер с причиной, а кнопка **«Состояние»** внизу
справа откроет диагностику с рецептом починки и кнопками «Перепроверить» /
«Исправить».

## Диагностика в приложении

Кнопка **«Состояние»** показывает состояние каждой подсистемы (состав зависит от
бэкенда):

| Проверка | Что значит |
|----------|-----------|
| Движок (llama.cpp) | Встроенный движок загружается, DLL на месте *(бэкенд llamacpp)* |
| Модель (GGUF) | Файл GGUF существует и читается *(бэкенд llamacpp)* |
| Ollama / Модель | Сервер отвечает и модель скачана *(бэкенд ollama)* |
| Docker (опционально) | Нужен только для расширенного веб-поиска |
| Веб-поиск | Встроенный работает всегда; расширенный — если включён SearXNG и он отвечает |
| Индекс проекта (RAG) | В индексе есть чанки |

## Кейсы

### Файл GGUF не найден (бэкенд llamacpp)

Диагностика: «GGUF не найден: <путь>».

1. Нажмите **«Исправить»** — мастер скачает модель из каталога с прогресс-баром
   и докачкой при обрыве.
2. Либо откройте страницу **«Модели»** и скачайте/импортируйте GGUF, затем
   **«Перепроверить»**.
3. Свой файл с диска: «Модели» → «Импорт с диска»; укажите путь в
   `config/config.yaml` (`gguf_path`).

### Ollama недоступна (бэкенд ollama)

Баннер: «Недоступно: Ollama». Диагностика: «нет соединения».

1. Установите Ollama с [ollama.com/download](https://ollama.com/download).
2. Запустите Ollama (иконка в трее / `ollama serve`).
3. Вернитесь в диалог «Состояние» и нажмите **«Перепроверить»**.

Модель не скачана: нажмите **«Исправить»** или выполните `ollama pull <модель>`.

### Веб-поиск не находит ничего

По умолчанию работает встроенный поиск через DuckDuckGo: ему нужен только
интернет. Проверьте подключение и повторите запрос.

### Расширенный поиск (SearXNG) не включается

Расширенный поиск включается вручную: меню **Правка → «Расширенный веб-поиск
(SearXNG в Docker)»**. Ему нужен Docker Desktop.

1. Docker Desktop не установлен — установите его с
   [docker.com](https://www.docker.com/products/docker-desktop/) или кнопкой
   **«Установить автоматически»** в мастере настройки (winget).
2. Docker Desktop установлен, но не запущен — при включении расширенного поиска
   Fluxion запустит его сам и дождётся движка; после первой установки Docker
   может потребоваться перезагрузка (WSL2).
3. Пока SearXNG не отвечает, запросы выполняет встроенный поиск — функция не
   пропадает.

Адрес SearXNG по умолчанию — `http://localhost:8080` (`web.searxng_url` в
config.yaml или переменная `SEARXNG_URL`).

### Docker установлен, но «демон не запущен»

Это важно только для расширенного поиска. Нажмите **«Исправить»** — Fluxion
запустит Docker Desktop и дождётся движка. Если Docker после установки
требует перезагрузку (WSL2) — перезагрузите компьютер и нажмите
**«Перепроверить»**.

### Агент и git

Кнопка **«Git: …»** в **«⚙ Настройки чата»** на странице «Чат» управляет git-инструментами агента:

- «Git: репозиторий» — агент может вызывать `git_status` / `git_diff` / `git_commit`
  и делает снимок рабочей папки перед первой правкой файлов (незакоммиченные
  изменения не трогаются; откат — `/rollback` в CLI).
- «Git: нет репозитория» — кнопка предложит **инициализировать репозиторий**
  (`git init` + первый коммит) или **работать без git** (инструменты отключаются,
  «поиск репозитория» прекращается).
- «Git: выключен» — кнопка предлагает включить инструменты обратно.

### Индекс пуст (RAG)

Диагностика: «индекс пуст». Чат отвечает, но без контекста проекта.

1. Откройте страницу **«Проект»**, выберите папку и нажмите
   **«Проиндексировать»**.
2. Первая индексация скачивает модель эмбеддингов — это может занять время.

### «Движок не подключён. Запустите приложение через python -m desktop_browser»

Такое сообщение означает, что окно открылось без движка (например, при запуске
исходников напрямую). Запустите приложение штатно: exe из сборки или
`python -m desktop_browser` (или `fluxion-desktop.bat`).

### Программа просит установить Ollama

Сборки Fluxion работают на встроенном движке llama.cpp, Ollama не нужна. Если
программа всё же её требует:

- версия ниже 0.11.1 — обновитесь: в старых версиях на компьютере без
  скачанной модели программа переключалась на Ollama;
- в `config/config.yaml` явно указано `backend: ollama` — удалите строку или
  укажите `backend: llama_cpp`;
- при запуске из исходников не установлен движок — запустите
  `fluxion-setup.bat`.

## Обучение (QLoRA)

### «Окружение обучения не найдено»

Нажмите **«Установить окружение обучения»** на странице «Обучение»: программа
проверит Python 3.12 и развернёт venv (несколько ГБ: torch, unsloth, peft, trl).

- **Python 3.12 не найден** — программа предложит установить его автоматически
  через winget (для текущего пользователя, без прав администратора, нужен интернет) или установите
  Python 3.11/3.12 вручную и повторите.
- **Full-сборка**: пак ставится офлайн из `training_pack\wheels` — интернет нужен
  только для Python, стек CUDA (torch cu126) качаться не будет.
- **Lite-сборка**: окружение докачивается из интернета; CUDA-стек занимает
  несколько ГБ.

### «PyTorch без поддержки CUDA» / «Unsloth cannot find any torch accelerator»

В окружении стоит PyTorch без поддержки видеокарты (так ставили версии до
0.12.3). Нажмите **«Переустановить окружение»** на странице «Обучение» под
строкой «Окружение обучения: готово»: окружение удалится и поставится заново со
сборкой PyTorch для CUDA. Если после переустановки программа пишет, что PyTorch
не видит видеокарту, обновите драйвер NVIDIA и перезагрузите компьютер.

### Обученная модель не появилась в списке моделей

Флажок **«Собрать готовую модель для чата (GGUF)»** в «Дополнительных
настройках» требует сборки llama.cpp: переменная окружения `LLAMA_CPP_DIR`
должна указывать на её папку (под флажком программа подсказывает, найдена ли
она). Без неё обучение заканчивается адаптером LoRA и объединённой моделью, а
готовая модель не собирается. Задайте `LLAMA_CPP_DIR` и запустите обучение
снова — модель появится в списке «Модель» в чате (подробнее —
[руководство по дообучению](guides/finetune.md)).

## Приложение упало

После сбоя программа пишет лог `<папка программы>\data\logs\crash-<дата>-<время>.log`
и показывает окно с кнопками «Копировать отчёт», «Отправить по email» и
«Открыть папку логов». Сама программа ничего не отправляет.

## CLI-эквивалент

```
❯ /status
```

Покажет состояние движка, модели, индекса и веб-поиска в терминале.

Не нашли свой случай? См. [FAQ](faq.md) или [Конфигурацию](configuration.md).
