# Fluxion 0.10.0 — что нового

Подробный технический список — в `CHANGELOG.md`. Здесь то же самое простыми словами.

## После обновления

1. **exe пересобирается автоматически**: `fluxion-update.bat` после проверок предложит собрать Lite или Full. Пересобрать позже без обновления: `fluxion-update.bat --build-only`.
2. **Движок выбирается сам.** Если установлен llama-cpp-python и модель скачана на странице «Модели», программа использует встроенный llama.cpp без строки `backend:` в `config.yaml`. Явная строка `backend: ollama` / `llama_cpp` / `api` по-прежнему главнее.
3. **Проверьте работу:** `fluxion-test.bat` → пункт 1 (1–2 минуты), затем пункт 4 (агент на вашей модели).
4. Если что-то пошло не так — `fluxion-update.bat --rollback` вернёт прежнюю версию.

## Агент: исправленные ошибки

| Что было | Что стало |
|---|---|
| Финальный ответ обрезался до первой строки — пропадал код и объяснения | Ответ приходит целиком |
| При падении тестов модель видела пустое «Error:» и чинила вслепую | Модель видит вывод pytest с причиной падения |
| После правки файла агенту запрещалось перезапустить тесты или перечитать файл («уже выполнялось») | Запрет сбрасывается после каждой правки |
| Модель сама дописывала «Observation: …», и это попадало в файлы вместе с markdown-разметкой ``` (задача t3 из догфуда) | Генерация останавливается перед «Observation:», разметка вырезается из файлов |
| Без pytest проверка писала «PASSED» | Честный статус «проверен только синтаксис» (жёлтым в интерфейсе) |
| Правка не срабатывала на Windows-файлах (CRLF) и из-за лишних пробелов в конце строк | Работает; окончания строк файла сохраняются |
| Агент видел только первые 3000 символов файла и искал только в `.py` | Постраничное чтение (`read_file файл 120-240`), поиск по всем текстовым файлам, новый инструмент `list_files` |
| llama.cpp игнорировал temperature/max_tokens из `config.yaml` | Настройки из конфига применяются |
| История шагов росла без ограничений | Старые шаги сжимаются при переполнении контекста |
| Лимит 8 шагов | 15 шагов |
| В чате ответ агента показывался дважды, а при ответе на другом языке — ещё и английская версия | Ответ показывается один раз; вместо английской версии — «Перевожу ответ…» |
| Код, который пишет агент, и блоки ``` в ответах выводились в чат простым текстом | Блоки кода моноширинным шрифтом; правки файлов — в виде diff |
| Агент думал на английском и тратил лишний шаг на перевод ответа | Агент сразу думает и отвечает на языке вопроса |
| Итоговый ответ мог не говорить, что сделано | Ответ называет созданные файлы, объясняет, как их запустить, и содержит код, если его просили |

## Агент: новые возможности

- **Структурированные вызовы инструментов.** С llama.cpp и Ollama каждое действие модели — JSON по схеме, которую движок проверяет на лету. Маленькая модель физически не может выдать неправильный формат. Если движок схему не поддерживает (старая Ollama), агент сам переходит на прежний текстовый формат. Отключить: `FLUXION_AGENT_FORMAT=text`.
- **Поиск по смыслу `search_code`** по проиндексированному проекту (RAG). Раньше индекс передавался агенту, но не использовался.
- Модели показываются только доступные инструменты: без записи в режиме чтения, без веб-поиска, если он не настроен.
- **Команда `/rollback`** в CLI отменяет все правки последнего запуска агента.

## Безопасность и сохранность данных

- **Главное: агент больше не прячет вашу незакоммиченную работу.** Раньше перед первой правкой он делал `git stash`, и ваши несохранённые изменения исчезали из папки. Теперь делается снимок, который файлы не трогает. Если у вас остались старые записи `fluxion-checkpoint` в `git stash list`, `/rollback` их вернёт.
- Исправлена редкая ошибка снимка (найдена тестами на Windows): правка того же размера, сделанная в ту же секунду, могла не попасть в снимок, и откат её пропускал.
- Агент коммитит только файлы, которые менял сам, и никогда — `.env` и ключи.
- Агент не может читать файлы вне папки проекта, а также `.env`, ключи и сертификаты — они не уходят в модель.
- Результаты веб-поиска помечаются для модели как недоверенные.
- Запрещены опасные параметры pytest, позволяющие выполнить чужой код.
- Токен Hugging Face больше не отправляется стороннему API-провайдеру.
- **Сервер:**
  - режим `FLUXION_SERVER_MODE=saas` (включён в Docker-образе): агент только читает, не запускает тесты, пользователь видит только свою папку;
  - в продакшене сервер не стартует без надёжного `FLUXION_JWT_SECRET` (публичный секрет из репозитория больше не используется);
  - CORS больше не открыт для всех сайтов — только localhost и VS Code, либо список из `FLUXION_CORS_ORIGINS`;
  - локальный сервер слушает только `127.0.0.1`, а не всю сеть;
  - в `docker-compose.prod.yml` обязателен пароль базы.

## Новые инструменты

- **`fluxion-update.bat`** — обновление из архива: резервная копия, замена файлов с сохранением ваших конфигов, проверка, откат (`--rollback`) и пересборка exe (Lite или Full). Перед сборкой проверяет PyInstaller, наличие движка llama.cpp и 7-Zip, после — что exe собран и движок внутри.
- Скрипты сборки используют Python из `.venv` проекта (раньше — системный из PATH) и умеют собирать без 7-Zip.
- **`fluxion-release.bat`** — выпуск новой версии на GitHub: проверки и тесты, коммит, тег, отправка и релиз со сборками. `--check` — только проверки.
- **`fluxion-test.bat`** — меню тестирования: быстрая проверка агента, все тесты по группам с понятной сводкой (недостающие пакеты — «пропущено», а не ошибки), проверка агента на реальной модели, полный замер качества.
- **Бенчмарк агента `eval/agent_bench`** — 36 реальных задач (вопросы по коду, создание, исправление, рефакторинг) с автоматической проверкой. Сравнивает старого агента, новый текстовый и новый JSON-режим. Показывает каждый шаг агента по мере выполнения и ограничивает задачу 15 минутами: зависшая задача засчитывается как проваленная и не останавливает замер. Инструкция: `eval/agent_bench/README.md`.
- Более 75 новых автоматических тестов на каждую исправленную ошибку.

## Чистка проекта

**Удалено:**
- старое десктоп-приложение `desktop/` (exe собирается из `desktop_browser`) и всё, что к нему относилось: `run_desktop.py`, `fluxion-desktop.spec`;
- `fluxion-desktop-browser.spec` — заменён Lite-вариантом;
- `fluxion-license.bat` — остался более новый `issue-key.bat`;
- `fluxion-deploy.bat` и `fluxion-web.bat` — дублировали другие батники;
- `scripts/export_training_package.py` — не использовался;
- папка `reference/` — посторонний учебный код.

**Перенесено** в `docs/internal/`: лог догфуда, дорожная карта, сценарий ролика. На сайт документации они не попадают.

**Батники теперь такие:**

| Батник | Назначение |
|---|---|
| `fluxion-setup.bat` | Установка: окружение `.venv`, зависимости, встроенный движок llama.cpp (Ollama не нужна), по желанию сервер |
| `fluxion-desktop.bat` | Запуск программы (раньше запускал старое приложение) |
| `fluxion.bat` | CLI |
| `fluxion-server.bat` | Сервер для VS Code |
| `fluxion-vscode.bat` | Установка расширения VS Code |
| `fluxion-test.bat` | Тесты и проверка агента |
| `fluxion-update.bat` | Обновление, откат, пересборка exe |
| `issue-key.bat` | Выпуск ключей |

Все батники запуска используют Python из `.venv` проекта, если он есть.

**Ошибки, найденные при чистке:**
- **Установка окружения для дообучения была сломана.** Из офлайн-пакета Full-сборки она падала с ошибкой, а онлайн ставила PyTorch и ML-стек дважды, причём второй раз без фиксированной версии. Причина — остаток неудачного слияния кода. Нашлось, когда тесты дообучения перенесли со старого приложения на новое: до этого проверялась только копия в старом.
- Процессу обучения снова передаётся путь к файлу лицензии: в старом приложении это было, в новом потерялось.
- Тесты десктопа при каждом запуске писали в вашу настоящую историю чатов `data\chats.json`. Теперь они работают с временным файлом.
- Расширение VS Code не запускалось: в его описании был указан несуществующий файл. Ветка `fluxion-vscode.bat` для случая «VS Code не найден в PATH» не работала вовсе.
- `fluxion-web.bat` создавал контейнер поиска без нужных настроек, и поиск получал ошибку 403. В старых `fluxion-setup.bat` и `fluxion-deploy.bat` ветка скачивания модели ломалась из-за скобок в тексте.
- `scripts/install_llamacpp.ps1` не мог установить движок в виртуальное окружение.
- Значок окна теперь квадратный и совпадает со значком exe; exe стал меньше примерно на 4,5 МБ.
- Обновление теперь удаляет файлы, убранные из проекта (список в `REMOVED_FILES.txt`); удалённое остаётся в резервной копии.

## Что изменилось в поведении

- Без `FLUXION_JWT_SECRET` в режиме разработки сессии веб-приложения сбрасываются при перезапуске сервера.
- Локальный сервер недоступен с других компьютеров сети (было `0.0.0.0`).
- Агент отказывается читать `.env`; при необходимости — параметр `allow_secret_read=True`.
- При отсутствии тестов в проекте статус проверки — «только синтаксис», а не «пройдено».
