# Агентный бенчмарк Fluxion

36 реалистичных задач для агента: вопросы по коду, создание модулей, исправление
багов, рефакторинг, ответы без инструментов и проверка «ничего не менять».
Каждая задача — маленький проект, запрос к агенту и автоматические проверки,
которые запускаются **после** работы агента.

| Категория | Задач | Что проверяется |
|-----------|-------|-----------------|
| qa | 10 | ответ содержит нужный факт (файл, значение, порт, версию); в т.ч. длинный файл, YAML, Dockerfile |
| chat | 2 | ответ без вызова инструментов, на языке вопроса |
| create | 8 | новый код проходит скрытые проверки; в т.ч. сценарий t3 из догфуда и тест с мутацией |
| fix | 10 | баг исправлен, тесты проекта **не изменены**; в т.ч. CRLF-файл, длинный файл, JSON-конфиг |
| refactor | 5 | новое поведение работает, старое не сломано |
| safety | 1 | при просьбе «ничего не меняй» файлы не изменены |

## Режимы

- `baseline` — замороженная копия агента до исправлений (`baseline_agent.py`);
- `text` — текущий агент, классический текстовый ReAct;
- `json` — текущий агент, структурированные вызовы по JSON-схеме.

Все режимы получают одну и ту же модель, лимит итераций (15), без RAG и
веб-поиска, без git — чтобы сравнивался только агент.

## Запуск

Нужно окружение разработки (не exe) с llama-cpp-python или Ollama и **pytest**:
агент запускает тесты проекта через него.

```bash
# 1. Проверить сами задачи (модель не нужна, секунды)
python -m eval.agent_bench --validate

# 2. Пробный прогон: 3 задачи, один режим (~2–3 минуты на CPU)
python -m eval.agent_bench --limit 3 --modes json

# 3. Полный замер
python -m eval.agent_bench --modes baseline,text,json --repeats 3 --out results/agent_bench/full
```

Модель и бэкенд берутся из `config/config.yaml` (или `--config путь`), то есть
замеряется ровно ваша настройка.

**Время.** На CPU (Qwen2.5-Coder-7B Q4, llama.cpp) задача занимает в среднем
~85 с. Один проход (36 задач × 3 режима = 108 прогонов) — около 2,5 часа, три
повтора — около 7,5 часа. Разумно сначала сделать один проход, а повторы
досчитать той же командой с `--repeats 3` и тем же `--out`: сделанное
пропускается.

Каждый шаг агента печатается по мере выполнения, так что долгая задача не
выглядит зависшей. `--task-timeout` (по умолчанию 900 с) ограничивает задачу:
лимит проверяется после каждого шага, задача с таймаутом засчитывается как
проваленная и видна в колонке Timeouts. Чаще всего долго работает режим
`baseline`: у старого агента нет stop-последовательностей и сжатия истории.

Результаты пишутся после каждой задачи: если прервать (Ctrl+C) и запустить ту
же команду с тем же `--out`, прогон продолжится с места остановки. На другом
компьютере лучше начать новую папку: время разных машин несравнимо.

## Результаты

В папке `--out`:

- `report.md` — сводка: доля решённых задач по режимам, среднее число шагов,
  время, ошибки инструментов, ошибки формата, срабатывания защиты от повторов,
  разбивка по категориям, попарное сравнение режимов и таблица по задачам;
- `results.jsonl` — сырые данные по каждому прогону;
- `meta.json` — модель, бэкенд и параметры генерации.

Пересобрать отчёт без запуска модели: `python -m eval.agent_bench --report results/agent_bench/full`.

`--keep` оставляет рабочие папки задач, чтобы посмотреть, что именно агент
сделал с файлами (путь сохраняется в `results.jsonl`).

## Как читать

При 36 задачах разница в 2–3 задачи может быть случайной. Доверять стоит
различиям, которые держатся на всех повторах и видны в попарном сравнении.
Если в отчёте есть предупреждение, что json-режим откатился на text, значит
бэкенд отклонил схему, и эти прогоны на самом деле измеряют текстовый формат.

## Свои задачи

Добавьте `Task` в `tasks.py`: фикстуру, запрос, проверки и эталонное решение.
`--validate` проверит, что эталон проходит проверки, а нетронутая фикстура —
нет. Лучшие задачи — те, на которых агент реально ошибался у вас или у
пользователей.
